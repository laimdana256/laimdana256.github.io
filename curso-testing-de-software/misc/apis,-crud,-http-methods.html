APIs, CRUD, HTTP methods

Qué es una API

Una interfaz de programación de aplicaciones (API) define las reglas que debe seguir una aplicación para comunicarse con otros sistemas de software. Los desarrolladores exponen o crean APIs para que otras aplicaciones puedan comunicarse con las suyas mediante programación. Por ejemplo, la aplicación de nómina expone una API que solicita el nombre completo de un empleado y un rango de fechas. Al recibir esta información, procesa internamente el horario del empleado y devuelve la cantidad de horas trabajadas en ese rango de fechas.

  • Las APIs ayudan a que diferentes aplicaciones se conecten y funcionen juntas sin problemas.
  • Permiten compartir datos y comunicarse sin exponer la lógica interna del sistema.
  • Las APIs se usan ampliamente en aplicaciones web, aplicaciones móviles, sistemas de pago y servicios en la nube.

Cómo funciona una API

Una API actúa como una capa de comunicación entre un cliente y un servidor, gestionando solicitudes y devolviendo respuestas para permitir el intercambio de datos entre aplicaciones.

  • Cliente → API (Solicitud): La aplicación cliente envía una solicitud a la API que contiene los datos requeridos, parámetros, cabeceras (headers) y detalles de autenticación.
  • API → Servidor (Reenvío de la solicitud): La API recibe la solicitud, valida los datos de entrada, aplica la lógica de negocio y reenvía la solicitud al servidor o base de datos correspondiente.
  • Servidor → API (Respuesta): El servidor procesa la solicitud, recupera o actualiza los datos y envía el resultado de vuelta a la API.
  • API → Cliente (Respuesta): La API formatea la respuesta (comúnmente en formato JSON o XML) y la envía de vuelta a la aplicación cliente.

Componentes de una API

Una API consta de varios componentes clave que definen cómo se comunican las aplicaciones e intercambian datos.

  • Endpoint de la API: una URL específica a través de la cual los clientes acceden a los recursos o servicios de la API.
  • Solicitud (Request): enviada por el cliente a la API para realizar una operación o recuperar datos del servidor.
  • Métodos HTTP: definen el tipo de acción que realiza una solicitud de API, como recuperar, crear, actualizar o eliminar datos (aquí es donde entra el concepto de CRUD).
  • Cabeceras (Headers): proporcionan información adicional sobre la solicitud o la respuesta, como detalles de autenticación, tipo de contenido y tokens de autorización.
  • Cuerpo de la solicitud (Payload): contiene los datos enviados desde el cliente al servidor, generalmente en formato JSON o XML.
  • Respuesta (Response): son los datos devueltos por el servidor tras procesar la solicitud de la API.
  • Códigos de estado HTTP: indican el resultado de una solicitud de API, como éxito, error del cliente o error del servidor.
  • Autenticación y autorización: la autenticación verifica la identidad de un usuario o aplicación, mientras que la autorización controla el acceso a recursos específicos.
  • Documentación de la API: proporciona detalles sobre los endpoints, formatos de solicitud, parámetros y estructuras de respuesta para ayudar a los desarrolladores a usar la API de forma efectiva.

Arquitecturas de API

Las arquitecturas de API definen la estructura, los principios de diseño y los métodos de comunicación utilizados entre las aplicaciones cliente y los servidores. Diferentes arquitecturas ofrecen distintos enfoques para construir y gestionar APIs.

REST, SOAP, GraphQL y gRPC son las arquitecturas de API más utilizadas para diseñar e implementar APIs modernas.

REST API

Una API REST (Representational State Transfer / Transferencia de Estado Representacional) permite la comunicación entre cliente y servidor a través de HTTP. Intercambia datos, típicamente, en formato JSON usando protocolos web estándar.

  • Usa métodos HTTP como GET, POST, PUT, PATCH y DELETE.
  • El cliente envía solicitudes a los endpoints (URLs) del servidor.
  • El servidor devuelve respuestas como JSON, XML, HTML o imágenes.
  • Mapea los métodos HTTP a operaciones CRUD (Create, Read, Update, Delete / Crear, Leer, Actualizar, Eliminar).

Nota: REST es un estilo arquitectónico que define cómo deben diseñarse las APIs, mientras que HTTP es el protocolo usado para transferir datos entre cliente y servidor. Trabajan juntos, pero no son lo mismo.

Qué es CRUD

CRUD son las cuatro operaciones básicas que se pueden realizar sobre datos persistentes (Por ejemplo un a base de datos) vine de las siglas:

  • Create (Crear) → añadir un nuevo registro o recurso.
  • Read (Leer) → consultar o recuperar datos existentes.
  • Update (Actualizar) → modificar un registro ya existente.
  • Delete (Eliminar) → borrar un registro.

Es un concepto genérico que aparece en casi cualquier sistema que maneje datos: bases de datos, aplicaciones, y también APIs En una API REST estas cuatro operaciones se mapean directamente a los métodos HTTP:

Operación CRUD Método HTTP típico
Create POST
Read GET
Update PUT / PATCH
Delete DELETE

Métodos HTTP comunes usados en API REST

En la arquitectura REST, los principales métodos HTTP son GET, POST, PUT, PATCH y DELETE, que se corresponden con las operaciones CRUD. Otros métodos menos comunes incluyen HEAD y OPTIONS.

1. Método GET

El método HTTP GET recupera un recurso. Si tiene éxito, devuelve los datos (normalmente en JSON o XML) con el código 200 OK; en caso de error, comúnmente devuelve 404 Not Found o 400 Bad Request.

GET /users/123

Esta solicitud obtiene los datos del usuario con ID 123.

2. Método POST

El método POST crea nuevos recursos. Si tiene éxito, devuelve el código 201 Created junto con una cabecera Location que apunta al nuevo recurso.

POST /users { "name": "Anne", "email": "gfg@example.com" }

Esta solicitud crea un nuevo usuario con los datos indicados.

Nota: POST no es seguro (safe) ni idempotente.

3. Método PUT

PUT se usa para actualizar o crear un recurso. Envía el recurso completo en el cuerpo de la solicitud y reemplaza el existente en la URL especificada.

PUT /users/123 { "name": "Anne", "email": "gfg@example.com" }

Esta solicitud actualiza el usuario con ID 123, o crea uno nuevo si no existe.

4. Método PATCH

PATCH se usa para actualizar parcialmente un recurso. Envía solo los campos que se van a modificar, en lugar de reemplazar el recurso completo.

PATCH /users/123 { "email": "new.email@example.com" }

Esta solicitud actualiza únicamente el correo electrónico del usuario con ID 123, dejando el resto de los datos sin cambios.

Diferencias entre PUT y PATCH

Tanto PATCH como PUT se usan para actualizar recursos en el servidor, pero difieren en cómo gestionan el proceso de actualización:

PUT PATCH
Reemplaza el recurso completo Actualiza solo los campos especificados
Debe enviar los datos completos Solo envía los cambios
Idempotente No siempre es idempotente
Ejemplo: actualizar todo el perfil de un usuario Ejemplo: cambiar solo el correo de un usuario

5. Método DELETE

Se usa para eliminar un recurso identificado por una URI. Tras una eliminación exitosa, devuelve el código de estado HTTP 200 (OK) junto con un cuerpo de respuesta.

DELETE /users/123

Esta solicitud elimina al usuario con ID 123.
