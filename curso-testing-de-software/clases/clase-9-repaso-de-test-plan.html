Clase 9 - Repaso de Test Plan

Test Plan — Repaso

¿Qué es?

Documento que describe la estrategia con la que se va a probar el producto. Se escribe al inicio del proyecto, no en paralelo a los test cases. Es planificación previa a cualquier prueba o testeo — en esta instancia todavía no existen los test cases.

Generalmente lo escribe el QA de mayor experiencia.

Referencias:

  • Ejemplo de test plan en la bibliografía de Drive del curso
  • [Buscar ejemplos de Test Plan en internet]
  • ISTQB (los exámenes son pagos, pero la bibliografía es gratuita)
  • Formato IEEE 829

Contenido de un Test Plan

1. Objetivos

Responde a: ¿cuál es el propósito de tener un proceso de testing en este caso?

  • Verificar que las funcionalidades implementadas cumplen los requisitos
  • Detectar defectos antes de la publicación
  • Reducir el riesgo de errores en producción
  • Validar los flujos críticos del negocio

2. Alcance (Scope)

Especifica qué entra y qué NO entra en el testing, en este momento, este contexto y esta versión de la aplicación.

Ejemplo: en un ERP (sistema que centraliza varias aplicaciones), se define qué módulos quedan dentro y cuáles fuera de la esfera de QA.

Pregunta pendiente: ¿quién establece qué se testea y qué no? Si no hay especificación, ¿el tester debe asumir que se testea todo lo posible?

3. Estrategia de testing

Responde a qué se va a testear y cómo. Puede ser tan simple como listar los tipos de testing a realizar:

  • Smoke
  • Functional
  • Regression
  • Exploratory

Se detalla qué funcionalidades se van a probar y cuáles no.

4. Ambiente de testing

Dónde se va a testear:

  • URL
  • Base de datos
  • Navegadores
  • Dispositivos

5. Criterios de entrada y salida

Entrada — responde a: ¿qué necesito para arrancar a testear?

  • Requisitos aprobados
  • Desarrollo finalizado
  • Ambiente QA disponible
  • Deployment realizado (código enviado de desarrollo a QA)
  • QA tiene acceso a la aplicación

Salida — define cómo se aprueba, como QA, cada funcionalidad testeada.

6. Riesgos

Riesgo Impacto
Ambiente QA inestable Alto
Retrasos en desarrollo Medio
Datos de prueba incorrectos Medio
Cambios de alcance durante el sprint Alto

7. Mitigaciones

  • Mantener comunicación diaria con Desarrollo
  • Tener datos de prueba preparados previamente
  • Validar el ambiente antes de empezar las pruebas
  • Ejecutar smoke testing después de cada deployment

8. Roles y responsabilidades

(pendiente de completar)

9. Herramientas

  • Jira — gestión de bugs
  • TestRail — casos de prueba
  • Chrome DevTools
  • Postman — pruebas de API
  • Slack — comunicación

10. Cronograma

Estimación de cuánto va a llevar cada tarea listada arriba.

11. Entregables

Documentos que QA entrega durante el proyecto:

  • Test plan
  • Test cases
  • Reporte de bugs
  • Reporte de ejecución
  • Reporte final de testing
  • Recomendación de release (Go / No Go)

12. Aprobaciones

Rol Nombre Estado
Pendiente / Aprobado
